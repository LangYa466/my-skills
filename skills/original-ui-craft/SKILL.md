# Original UI Craft — 原創高階介面設計與前端工藝完全手冊

> **核心信條**：好的設計不是挑選一個「看起來不錯的佈局模板」再換配色與字體，而是先潛入對象的靈魂深處，找到只屬於它的精神母題與真實資訊密度，讓空間拓撲、材質溫度、排版聲部與克制互動像植物一樣自然生長出來。**換一個專案，就必須長出完全不同的形狀。**

---

## 第 0 章｜這份 Skill 的存在意義與使用原則

### 0.1 為什麼需要一份長篇、徹底的第一性原理設計手冊？

大多數簡短的設計規則（例如「用好字體、多留白、避免藍紫漸層」）之所以失效，是因為它們只給出**表層禁令**，卻沒有改寫底層的**思考順序**。當模型接到「重新設計 UI」指令時，如果沒有一套完整的思維作業系統，大腦會本能地掉進三個連續的陷阱：

1. **第一層陷阱（通用 AI 模板）**：直接召喚訓練資料的統計平均值——Inter 字體、藍紫微光、毛玻璃圓角卡片、3 張一模一樣的 Feature Box、`transition: all` 與拖慢首屏的入場淡入。
2. **第二層陷阱（反 AI 的新 AI 模板）**：為了避開第一層，立刻滑向 2025–2026 年最氾濫的「偽編輯風」——暖奶白 `#f7f5f0`＋陶土紅點 `#c4452b`＋斜體襯線字（甚至強行讓中文變成難看的假斜體）＋1px 細線方格＋大寫等寬標題＋`01/02/03` 編號清單。
3. **第三層陷阱（工整但冰冷的老套極簡）**：拿掉卡片與紅點後，滑向醫院純白 `#fafafa`＋工業藍 `#1d4ed8`＋標準的「頂欄 → 居中主體／左右分欄 → 列表 → 頁尾」。雖然乾淨、結構工整、挑不出明顯毛病，但因為**底層空間骨架依舊老套、缺乏情緒溫度、沒有讓人驚豔的原創想法**，看完只會覺得「不錯，但很一般」。

這份手冊的存在目的，就是把**從第三層破局到「開放、高階、有溫度、不花哨、別人沒試過」的完整思維與工程工藝**，毫無保留地沉澱成一套跨專案、跨領域、永不過時的作業系統。

### 0.2 本手冊的「三不鎖死」鐵律

使用這份 Skill 時，必須嚴格遵守以下三條反教條原則：

- **不鎖死風格（Style-Agnostic）**：本手冊追求的是「有溫度與材質真實感」，而非永遠使用暖棉紙、暖黃銅或日系和紙。冷調礦石、霧面陽極氧化鋁、深暗房銀鹽灰、墨綠建築石膏、高對比瑞士印刷黑，只要契合對象氣質，都是高階選擇。
- **不鎖死佈局（Layout-Agnostic）**：絕不因為某個專案的「偏心原點＋弧形星群＋貝茲連線」非常驚豔，就把同一套空間佈局複製貼上到下一個專案。**重複使用自己的奇招，奇招在第二次就淪為老套模板。**
- **不鎖死技術棧（Stack-Agnostic）**：無論目標專案使用 Astro、Next.js、Vue、Svelte、原生 HTML/CSS/JS，或任何 CSS 方案（Vanilla CSS、Tailwind v4、CSS Modules），底層的空間幾何、色彩光學、排版紀律、無障礙與效能工程準則全部通用。

## 第 1 章｜使用者審美畫像與核心品味精準解碼（Taste Profile）

要做出讓使用者一眼心動、覺得「對，這就是我要的高階感」的設計，必須精準理解這套審美背後真正看重的是什麼，以及最反感的是什麼。以下從真實多輪設計迭代的回饋、倉庫歷史與作品氣質中，提煉出 **10 條核心品味坐標**。

### 1.1 十條核心審美坐標

1. **極度敏感於「AI 味」與「套版感」**
   - 能在一秒內看穿任何統計平均值的設計骨架（無論包裝成現代 SaaS、Bento Grid、還是偽高級編輯風）。
   - 拒絕被「安全但無聊」的標準結構敷衍；寧可大膽開闊、讓人耳目一新，也不要四平八穩的標準答案。
2. **追求「開放性思維」而非封閉式排版**
   - 反感把所有東西塞進中間一條窄窄的 `700px` 圓柱裡上下捲動，也反感被四面牆壁、死板方框或硬性左右對切關住的「儀表板監獄感」。
   - 偏愛把整個視窗視為呼吸的開放空間，元素之間靠視覺張力、比例節奏與大片留白（間 / Ma）建立對話，而不是靠邊框把它們隔開。
3. **「不花哨」是絕對底線，高階感來自克制而非堆砌**
   - 強烈排斥視覺噪音：不要浮誇的 3D WebGL 旋轉物、不要霓虹光球、不要一直閃爍呼吸的假在線綠點、不要拖泥帶水的入場淡入動畫（甚至在過往 git commit 中主動刪除過入場動畫）。
   - 動效必須像高級機械相機或墨水落在紙上：平時安靜無聲，只有當人去觸碰、滑過時，才給出精準、溫柔且有物理實感的回饋。
4. **重視「人的溫度」與情緒共鳴**
   - 純粹理性冷靜的黑白灰＋工業藍表單雖乾淨，卻容易顯得疏離冷漠。
   - 真正打動人的是「有個人溫度與想法」的設計：能把創作者自己的一句話、一個標誌、一種生活與技術的狀態，轉化成可感知的色溫、材質與互動詩意。
5. **內容潔癖：寧缺勿濫，絕不為了填滿版面而硬塞東西**
   - 非常清楚「我的網站要放什麼、不要放什麼」（例如不硬塞 GitHub 倉庫列表、不保留多餘的探針／友鏈／假路由數據）。
   - 面對精簡的內容，正確做法是**用高階的空間構圖把「少」變成一種從容的氣場**，絕不是硬拉大卡片或塞進一堆湊數文字。
6. **高度尊重真實個人識別符號**
   - 站點已有的真實符號（例如俐落的狼頭剪影 favicon、真實的語言清單、真實的網路身分 `AS213876`、真實的聯絡方式）是設計的最高優先級素材。
   - 不要用無意義的通用幾何裝飾（例如隨機畫個彩色圓點、假裝飾線條）去替代對象本身已經具備辨識度的標誌。
7. **欣賞細膩的印刷級與工程級排版修養**
   - 對中英混排的觀感極為敏銳（例如反感中文假斜體、注重繁體／簡體語境的精準呈現、欣賞等寬字體與人文宋體／現代無襯線之間的張力）。
   - 在意作品底層的「乾淨度」：輸出 HTML 無多餘註解、載入極快、程式碼結構整潔、不夾雜無用依賴。
8. **喜歡「別人沒試過，但看起來毫不費力」的獨創感**
   - 獨創不等於怪異、難以使用或看不懂。最高級的獨創是：**第一眼覺得「哇，從沒看過這樣排的網站」，第二眼卻覺得「理所當然、非常順手、資訊一目了然」**。
9. **偏愛直達與實用微細節，討厭多餘儀式感**
   - 像點擊直接複製 ASN／Email、系統深淺色自動跟隨、語系自動偵測與無縫切換、滑過即預覽去處註解，這些不佔版面卻真正順手的微工藝極度加分。
   - 相反，複雜的多層選單、多餘的「歡迎來到我的網站」廢話、炫技卻沒用的按鈕，全部減分。
10. **同時看重淺色與深色模式各自的完整氣質**
    - 不是「做一個主色，另一個隨便反白敷衍」。淺色要有紙本／日光的溫潤通透，深色要有深夜工作室／暗房的沉靜護眼，兩種模式都必須自成一體。

### 1.2 三組關鍵邊界對照表（拿捏精準尺度的羅盤）

| 維度 | 我們追求的境界（高階） | 容易滑偏的誤區（低階／花哨／老套） |
| :--- | :--- | :--- |
| **開放性思維 vs 花哨** | 打破預設頂欄／卡片／豎流，讓元素在 2D 空間中透過比例、弧線、軸線與留白建立張力；只保留 **1 個**與母題合一的精緻互動。 | 滿螢幕粒子飄浮、滑鼠爆炸特效、炫彩漸層邊框、3D 傾斜卡片、花俏字體疊字、看不清內容的實驗藝術亂排。 |
| **有溫度 vs AI 偽文藝** | 從實體材質（棉紙、石材、墨色、黃銅、霧鋁）與對象真實語氣出發，色溫微調克制、留白從容、細節有呼吸感。 | 套用固定 `#f7f5f0`＋`#c4452b`＋斜體襯線公式、強迫中文假斜體、寫出「Hi, I'm a passionate developer」這類假文青套話。 |
| **克制極簡 vs 冰冷空洞** | 資訊少而精，畫面安靜，但有清晰視覺焦點、細微光影與質地、精準微互動與強烈個人印記，耐看且有記憶點。 | 純白底黑字表格、缺乏視覺重心、把少量內容放進大空白中顯得孤立尷尬、零觸感回饋、看過就忘。 |

## 第 2 章｜為什麼最後一版設計「做得好」——深度解剖成功基因

> **注意**：本章剖析的不是「叫你以後照抄這個設計」，而是解剖它背後**五條可遷移至任何專案的底層成功法則**。

### 2.1 空間基因：用「確定性網格」撐出「無邊界自由感」

- **破除了什麼慣性**：完全移除了帶邊框的頂欄（Navbar）、底欄橫條（Footer Bar）、卡片容器（Card）、列表框線與左右分割牆。
- **為什麼不亂**：表面上看，標題在左上、切換在右上、狼頭印記在偏左黃金點、五個去處沿弧線懸浮在右側、語言在左下、落款在右下——彷彿自由散落在一張大畫布上。但底層其實是嚴格的 **3×3 CSS Grid（`minmax` 彈性軌道）**，從數學上保證了在任何螢幕寬高與縮放比下，六個區域**永遠不可能重疊碰撞**。
- **可遷移法則**：**視覺上要「打破框架、無拘無束」，工程底層必須「嚴密精準、絕不崩壞」**。自由感是算出來的，不是用 `position: absolute` 亂貼出來的。

### 2.2 敘事基因：把「文字內容」升維成「空間結構與互動」

- 這個專案最動人的一句文案是**「這裏是我在世界上的痕跡」**，最核心的技術身分是 **`AS213876`（自治系統）**。
- 普通做法：把這句話用大字印在 `<p>` 裡，把 `AS213876` 放進一個標籤裡——結束。
- 升維做法：
  1. **原點（Origin）**：狼頭剪影不再是左上角裝飾小圖，而是整個空間場的「座標原點」，延伸出漸隱十字軸線。
  2. **軌跡（Trace / Route）**：五個去處與六種語言是空間中的「航點（Waypoints）」，靜止時以極淡鉛筆輔助弧線相連；當人將游標移向任一航點，一條暖銅色三次貝茲曲線從原點流暢「繪製」過去，原點下方同步浮現該航點的網域與註解——同時隱喻了 **BGP 路由路徑**與**人生留下的痕跡**。
  3. **筆觸（Ink Filament）**：滑鼠輕輕滑過空白紙面時，留下一縷極細（`1px`、低透明度）並在 0.76 秒內蒸發的暖色墨絲——把「痕跡」從靜態文字變成可觸碰的詩意體驗。
- **可遷移法則**：**最高級的介面沒有「裝飾品」，因為每一個視覺與動態元素都是核心內容的物理化身。**

### 2.3 材質與色溫基因：用「極低飽和微質地」取代「裝飾元素」

- 淺色使用暖棉紙 `#f2efe9` 配暖墨 `#1d1b18` 與焙赭銅 `#9e532b`；深色使用深夜暖墨 `#10100e` 配燭光米白 `#eae5dc` 與暖黃銅 `#d4945c`。
- 疊加兩層幾乎看不見但極具決定性的材質細節：
  - 全域 `opacity: 0.032` 的 SVG `feTurbulence` 紙纖維微顆粒。
  - 以原點（`36% 48%`）為圓心的 `4.5%–5.5%` 極淡漫射柔光。
- 結果：不靠任何插畫、照片、陰影或漸層卡片，整張畫面就具備了類似博物館版畫與實體手工紙的溫潤厚度。
- **可遷移法則**：**溫度來自「光線與材質的微妙偏差」，而非大面積高飽和上色。**

### 2.4 靜中有活基因：克制的張力與零負擔效能

- **靜止時 100% 安靜**：沒有任何物件自己亂動、閃爍或旋轉，打開瞬間即可閱讀。
- **互動時層次分明**：懸停某個去處時，該節點亮起、弧線繪製、原點低語切換、同組其餘項目透過 `:has()` 柔退至 `opacity: 0.34`——所有視覺訊號齊心指向同一個焦點，絕不彼此打架。
- **效能零浪費**：Canvas 墨痕只在滑鼠移動與淡出期間執行 `requestAnimationFrame`，淡出完畢立刻中止迴圈（0% CPU）；SVG 貝茲路徑預先快取並在 `ResizeObserver` 與字體就緒時才重算。
- **可遷移法則**：**高階互動的標準是「不觸碰時像一幅靜畫，觸碰時像一件活物，鬆手後不留負擔」。**

### 2.5 細節誠實度基因：看不見的地方一樣不妥協

- 實測檢視了 `favicon.ico` 內部各幀像素，發現原本圖示帶有一層白底圓角方塊，若直接反轉在深色模式會露餡；於是提取出純透明去背的 `160×160` Retina Alpha 遮罩，透過 CSS `mask`＋`currentColor` 完美融入明暗與懸停色。
- 用 CSS 自訂屬性 `--wolf-mask` 共用 `-webkit-mask` 與 `mask`，避免打包工具將圖片重複內嵌兩次。
- `withRef` 工具自動跳過 `mailto:` 與 `t.me`，確保原生郵件與 Telegram 喚起乾淨無污染。
- 行動端（`≤ 900px`）果斷卸除 SVG 弧線與 Canvas 墨痕，將原點收斂至頂部、弧形星群轉為俐落細線單列，並確保小螢幕點擊複製仍有獨立可見回饋。

## 第 3 章｜從零開始的六階段原創設計作業流程（End-to-End SOP）

未來接到任何 UI 設計、重構或視覺打磨任務，嚴格按以下六階段推進，跳過任何一步都容易退回老套模板。

### Phase 1：對象考古與素材鑑識（Pre-Design Forensics）

在動任何 CSS 之前，必須完成五項盤點：

1. **檢視倉庫歷史與偏好線索**：
   - 查看最近 10–20 筆 git commits，確認過去嘗試過哪些風格、為什麼改掉、曾主動刪掉過什麼（例如刪過動畫、刪過多餘連結、要求零註解等）。
2. **像素級檢查所有現有視覺資產**：
   - 實際打開／讀取現有的 Logo、Favicon、頭像、插圖，確認其主色調、筆觸氣質（銳利幾何 vs 圓潤手繪）、透明通道與深淺背景相容性。
3. **盤點真實資料結構與數量**：
   - 列出每一條真實存在的資訊與其角色（主身分、副身分、行動連結、技術標籤、即時狀態、核心功能操作等）。
   - **鐵律**：絕不私自捏造假數據、假指標、假專案、假評價，也不擅自塞入使用者沒要求展示的區塊。
4. **語氣與語境判讀**：
   - 判斷這是「詩意個人空間」、「硬核工程工具」、「內容閱讀場」、「高轉換產品頁」還是「高密度作業系統介面」。
   - 確認支援的所有語系（繁體中文、簡體中文、英文、日文等）及文字長度差異倍數。
5. **明確界定邊界**：
   - 確認不能破壞的既有功能（SEO、Open Graph、JSON-LD、Analytics、路由規則、快取標頭、既有資料層）。

### Phase 2：母題提煉引擎（Metaphor-First Engine）

針對目前專案回答這三個問題，寫不出具體答案就**絕不開始寫碼**：

1. **核心母題（Core Metaphor）是什麼？**——如果這個網站是一件真實世界裡的物品或空間，它會是什麼？

### Phase 4：色溫材質與排版聲部設計

- 先定義語意 Token（`--bg`、`--fg`、`--fg-2`、`--fg-3`、`--hairline`、`--accent`），嚴禁在元件樣式裡散落寫死的色碼。

- 確立清晰的字體聲部（主敘事、介面、等寬座標）與流體尺度（`clamp()`），嚴格遵守 CJK 排版紀律（第 7 章）。

### 4.2 十大空間拓撲詳解與 CSS 骨架

#### 模型 1：黃金偏心開放座標場（Open Cartographic Field）
- **空間特徵**：無頂欄、無底欄條、無外框。整個視口是一個 3×3 開放座標場，核心視覺標誌（Origin）落在偏左黃金交點（約 X: 35–38%, Y: 45–50%），四週依視覺重力安排標題、控制、目標與落款。
- **適用**：資訊極精簡、重視詩意與個人氣場的網站。
- **防碰撞 CSS Grid 骨架**：
```css
.field {
  position: relative;
  width: 100%;
  max-width: 102rem;
  min-height: 100svh;
  margin: 0 auto;
  padding: clamp(1.75rem, 4.5vh, 3.5rem) clamp(1.5rem, 4.8vw, 4.75rem);
  display: grid;
  grid-template-columns: minmax(14rem, 1.08fr) minmax(12rem, 0.92fr) minmax(17rem, 1.15fr);
  grid-template-rows: auto 1fr auto;
  column-gap: clamp(1rem, 2.8vw, 3rem);
  row-gap: clamp(1.25rem, 3vh, 2.25rem);
}
/* Col 1-2 Row 1: 主標 | Col 3 Row 1: 浮動控制 */
/* Col 1-2 Row 2: 黃金偏心原點 | Col 3 Row 2: 右側目標區 */
/* Col 1-2 Row 3: 左下輔助群 | Col 3 Row 3: 右下落款 */
```

#### 模型 2：拋物弧線／重力星群排布（Orbital & Parabolic Constellation）
- **空間特徵**：打破「所有項目左邊界死板對齊成垂直表單」的單調，讓 4–7 個入口依對稱拋物線或溫和對角階梯錯落（例如用自訂屬性 `--arc: 2, 1, 0, 1, 2` 計算水平縮排），視覺上自然環抱對側焦點。
- **關鍵紀律**：錯落必須有明確的數學對稱或黃金梯度，並搭配精細的圓點／航點錨記，讓大腦一眼辨識為「刻意設計的軌道」而非「忘記對齊」。
```css
.constellation-item {
  display: flex;
  align-items: center;
  gap: 0.85rem;
  padding-left: calc(var(--arc, 0) * 1.45rem);
}
```

#### 模型 3：全視口雙軸張力海報（Diagonal Exhibition Poster）
- **空間特徵**：靈感源自 Tokyo TDC 展覽海報。不把標題與內文疊在一起，而是將超大尺度展示字壓在**左上或左下**，將簡介、行動入口或動態元素錨定在**正對角（右下或右上）**，中間保留巨大的純淨空場，製造極強的空間張力。
```css
.poster {
  min-height: 100svh;
  padding: clamp(1.5rem, 4vw, 4rem);
  display: grid;
  grid-template-columns: repeat(12, minmax(0, 1fr));
  grid-template-rows: auto 1fr auto;
}
.poster-giant  { grid-column: 1 / 8; grid-row: 1 / 3; align-self: end; }
.poster-action { grid-column: 9 / 13; grid-row: 2 / 4; align-self: start; }
```

#### 模型 4：破格 12 欄呼吸走廊流（Broken 12-Column with *Ma* Corridors）
- **空間特徵**：用於有多個樂章的長滾動頁面。全頁統一使用寬廣的 12 欄網格（`max-width: 84rem`），但**每一屏刻意改變左右比例並保留至少 1 條空白走廊欄**（例如第 1 屏 `1–7` 配 `9–12`、第 8 欄空白；第 2 屏 `1–12` 全寬橫掃；第 3 屏 `1–6` 配 `8–12`、第 7 欄空白）。
- **為什麼高階**：使用者往下滾動時，每進入一段新內容，空間節奏就換一次呼吸方式，完全沒有「一直在看同一個重複模板」的疲勞感。
```css
.band-12 {
  display: grid;
  grid-template-columns: repeat(12, minmax(0, 1fr));
  column-gap: clamp(1rem, 2.5vw, 2.5rem);
}
.hero-left  { grid-column: 1 / 8; }
.hero-right { grid-column: 9 / 13; } /* Col 8 刻意留白 */
```

#### 模型 5：瑞士垂直鉛垂線邊注（Swiss Marginalia Monograph）
- **空間特徵**：所有區塊共享完全相同的兩欄定義（`9.5rem minmax(0, 1fr)`），在整個頁面形成一條貫穿首尾的無形垂直鉛垂線。左欄只放極克制的元資料、時間或章節名；右欄承載所有核心敘事、目錄與連結，搭配負邊距光學出血懸停。
- **適用**：個人檔案、長文專欄、更新日誌（Changelog）、極簡履歷。
```css
.marginalia-band {
  display: grid;
  grid-template-columns: 9.5rem minmax(0, 1fr);
  column-gap: 2.25rem;
  padding: 2rem 0;
  border-top: 1px solid var(--hairline);
}
```

#### 模型 6：無陰影微色階建築平面（Tonal Plane Architecture）
- **空間特徵**：徹底棄用圓角浮動卡片與 `box-shadow`，整個視口由 2–4 塊緊密咬合的建築平面組成（主空間 `--bg` 與鄰接功能室 `--bg-pane` 僅差 2%–4% 亮度，交界僅以 `1px` 極細線分隔）。懸停某個區塊或列表帶時，該區塊提亮為 `--bg-lift` 並在軸線滑出 `2px` 強調色邊條。
- **適用**：高質感開發工具、監控面板、非對稱雙窗空間。
```css
.tonal-stage {
  flex: 1;
  display: grid;
  grid-template-columns: minmax(0, 1.32fr) minmax(24rem, 1fr);
}
.tonal-left  { background: var(--bg); }
.tonal-right { background: var(--bg-pane); border-left: 1px solid var(--hairline); }
```

#### 模型 7：邊緣脊柱與角落印章（Edge-Spine & Corner-Stamp Canvas）
- **空間特徵**：放棄水平頂欄，改在視口最左側立一條極細（`3rem–3.75rem`）的垂直建築脊柱（放置標誌、極小直排等寬識別與主題開關），右側 95% 成為純粹不受干擾的開闊展場，語言切換與版權如版畫落款般靜置於右上與右下角落。
- **注意**：中文直排只適合用於極克制的邊緣座標或印章感元素，正文仍保持水平易讀。

#### 模型 8：全寬印刷大報層次流（Typographic Broadsheet）
- **空間特徵**：借鏡瑞士與日本高級印刷大報。以「全寬超大標題帶 → 多欄不等寬文字與目錄索引 → 細線分隔的精簡附註欄」構成，完全以文字密度與線條粗細建立視覺秩序，零圖示噪音、零裝飾插圖。
- **適用**：出版平台、設計評論、開源宣言、研究實驗室網站。

#### 模型 9：雙欄對照手稿（Parallel Ledger & Footnote Stream）
- **空間特徵**：左側是流暢的敘事或文檔正文，右側是緊隨對應段落的實時範例、註腳、程式碼或網路拓撲圖（透過 `position: sticky` 溫和停駐），讓「解釋」與「實證」永遠並肩呈現。
- **適用**：API 文件、技術深潛文章、工具展示頁。

#### 模型 10：無框精密儀表台（Zero-Chrome Instrument Deck）
- **空間特徵**：面向工程師的即時數據或操控介面。拿掉多餘標題橫幅、裝飾圖示與厚重卡片內距，所有數據嚴格採 `tabular-nums` 對齊，關鍵指標大字突顯、次要參數小字微灰、控制項直接嵌入邊角細線中，把 90% 視口面積還給真正的數據本身。

### 4.3 桌面 2D → 行動端 1D 優雅重組公式

開放式 2D 佈局最常見的翻車點是「電腦上超酷，手機上擠成一團」。必須遵守五條響應式降級原則：

1. **果斷斷捨離視覺連線**：SVG 跨區貝茲連線、桌面端游標 Canvas 筆觸、大面積十字軸線，在 `≤ 900px` 應直接 `display: none`，不要在窄螢幕硬畫擠在一起的線。
2. **用 `grid-row` / `order` 重排閱讀優先序**：在桌面端偏心放置的視覺原點，在手機端可以自然收斂為頂部小巧徽章（例如 `64px → 40px`），緊接著呈現姓名與核心介紹，再進入主要去處與次要標籤。
3. **取消水平弧線縮排**：手機端將所有錯落縮排歸零（`padding-left: 0`），改用清晰的 `1px` 極細分隔線與充足縱向觸控熱區（每行高度 ≥ `48px`）。
4. **放大操作控制項觸控面積**：桌面端精緻的 `28px`（`1.75rem`）語系／主題按鈕，在手機端（`≤ 640px`）應放寬至 `32px–36px`（`2rem–2.25rem`），避免誤觸。
5. **檢驗最長語系換行**：務必在 `375px` 寬度下測試英文等長字元語系，確保描述與網域透過 `flex-wrap: wrap` 或 `text-overflow: ellipsis` 優雅換行，絕不出現水平捲動條（`overflow-x` 爆版）。

## 第 5 章｜反 AI 味完全免疫系統（三代套版特徵解剖與根除清單）

設計前、設計中、設計後，必須用這份免疫清單做全面體檢。

### 5.1 第一代 AI 味（Generic SaaS Slop）黑名單

| 禁用特徵 | 為什麼要徹底根除 | 替代思路 |
| :--- | :--- | :--- |
| 預設 Inter＋靛藍／紫紅漸層光暈 | 90% AI 生成頁的出廠指紋，毫無辨識度 | 從真實材質與對象特徵提取色盤，用克制單色強調取代漸層 |
| 深色背景配浮動模糊彩色光球（Blob / Mesh Glow） | 視覺廉價、俗氣花哨、分散對內容的專注 | 最多使用單點 ≤ 5% 不透明度的微弱環境柔光，或純粹靠材質顆粒 |
| 毛玻璃卡片（`backdrop-filter: blur()`＋半透明白邊框） | 為了顯得「酷」而加的無意義塑膠質感 | 拿掉盒子，直接讓文字呼吸在畫布上；若需分區改用 2%–4% 微色階 |
| 三張一模一樣的功能卡片（左上小圖示＋粗體標題＋兩行廢話） | 填表式思維的最高象徵，視覺呆板 | 改用開放目錄行、弧形星群、對照索引或非對稱敘事 |
| 全域 `transition: all 0.3s ease` | 導致頁寬調整、字體切換或焦點變化時出現廉價黏滯感 | 嚴格指定單一屬性（`color`、`transform`、`opacity`）＋140–240ms 物理曲線 |
| 頁面載入時逐塊延遲淡入（`fadeInUp` stagger） | 拖慢閱讀節奏、刻意表演感重、老套 | 首次繪製即完整呈現，讓動態只回應使用者的真實操作 |
| 空洞行銷廢話（"Passionate full-stack developer crafting digital experiences"） | 一看就是機器寫的公關空話 | 只放真實、簡練、有人味的原話或事實 |

### 5.2 第二代「反 AI」的新 AI 味（Editorial Cliché Slop）黑名單

> **高度警惕**：許多新模型為了逃離第一代紫光漸層，已經集體形成了一套新的固定公式！只要同時命中 3 項以上，在內行眼中一樣是濃濃 AI 味：

- **公式色盤**：無腦套用 `#f7f5f0` 暖米紙＋`#c4452b` 陶土紅點。
- **假斜體襯線**：無腦套用 `Newsreader` italic 或 `Fraunces` italic 寫標語，甚至直接作用到中文上產生瀏覽器假斜體。
- **裝飾小圓點**：在左上角網域旁放一個沒有實質狀態意義的 `6px` 紅色／綠色圓點（`● domain.io`）。
- **細線方格矩陣**：把 3 個連結與 6 個技能塞進 `gap: 1px; background: var(--rule); border: 1px solid var(--rule)` 的對稱方格格子裡，每格右上角放一顆小箭頭。
- **全大寫加寬等寬區塊標題**：到處出現 `font-size: 11px; text-transform: uppercase; letter-spacing: 0.1em;` 的 `01 // ABOUT`、`02 // SKILLS`、`03 // LINKS`。

**破除之道**：就算某個專案確實適合編輯感或暖紙感，也必須**破除上述固定組合**——改用真實個人標誌、正體中文字型、開放非對稱空間、專屬物理母題互動，並根據素材重新校準色溫。

### 5.3 第三代「冷感極簡病」（Sterile Minimalism）診斷

- **症狀**：雖然沒有任何花哨裝飾，但畫面像一份醫院檢驗單或 Notion 空白模板——刺眼純白 `#ffffff`／冷灰 `#fafafa`、預設系統藍 `#1d4ed8`、工整橫條列表從頭排到尾。
- **解藥**：注入**材質溫度**（微色溫底色、極淡紙紋或石感）、注入**空間勇氣**（打破居中單柱、敢留大片空白、敢做非對稱重心）、注入**一個有靈魂的微互動**。

### 5.4 結構與細節紅旗（Structural Red Flags）

1. **重複展示同一個標誌**：頂欄放一顆小狼頭、主畫面又放一顆大狼頭、頁尾又放一顆——每個標誌只該在最具份量的位置出現一次。
2. **硬寫會過期的靜態數字**：把 GitHub Star 數（如 `★ 24`）或靜態追蹤者人數寫死在 HTML 裡，過一週就失真。若沒有即時資料源，就用永不過期的本質屬性（語言、領域、功能）取代。
3. **無差別污染所有外連**：用 `withRef()` 幫所有連結加 `?ref=domain` 時，如果不判斷協定，會把 `mailto:` 弄壞，或讓 `t.me/` 在部分客戶端深層喚起異常。
4. **不經確認亂塞內容**：沒經過同意就幫使用者塞入整排倉庫清單、虛構「關於我」長文或假時間軸，會直接稀釋主頁的純粹度。

## 第 6 章｜色彩學、光感與實體材質手冊

### 6.1 墨階數學架構（永不過時的 Token 體系）

無論挑選哪種氣質的色盤，每一套主題都必須以這 **8 個語意 Token** 為骨架，禁止在 CSS 規則中直接硬寫色碼：

```css
:root {
  --bg: ...;              /* 畫布主底色（承載材質色溫） */
  --bg-glow: ...;         /* 極淡單點環境柔光（≤ 5.5% 不透明度，可選） */
  --fg: ...;              /* 主墨色（標題、核心文字，對比度 ≥ 12:1） */
  --fg-2: ...;            /* 次墨色（內文、註解，對比度 ≥ 5.5:1，穩過 AA） */
  --fg-3: ...;            /* 淡墨色（座標、網域、次要標籤，對比度 ≥ 3.2:1） */
  --hairline: ...;        /* 標準 1px 結構細線（以 --fg 的 9%–11% 透明度構成） */
  --hairline-strong: ...; /* 強調細線／底線（以 --fg 的 22%–26% 透明度構成） */
  --accent: ...;          /* 全場唯一手術刀強調色（淺／深主題各自獨立校準） */
  --accent-ink: ...;      /* 落在 --accent 底上的反色文字（用於 ::selection） */
  --hover-pad: ...;       /* 極輕微懸停底色（4.5%–6% 透明度） */
  --active-pad: ...;      /* 啟用態輕量底色（8%–11% 透明度） */
}
```

### 6.2 為什麼暗色模式絕不能只是淺色的「數學反色」？

- **人眼對暗底高飽和色更敏感**：淺紙上沉穩的深焙銅 `#9e532b` 直接搬到黑底上會顯得發暗髒濁；必須提高明度、微降過衝飽和度，轉為溫潤發亮的暖黃銅 `#d4945c`（在 `#10100e` 上對比度達 `7.3:1`）。
- **暗底需要更精確的色溫連貫**：若淺色帶暖色調，深色應落在暖墨黑（如 `#10100e` / `#131210`）配暖燭白（`#eae5dc`）；若淺色是冷礦石，深色才落在冷碳黑（`#0b0c0f`）配冷雪白（`#edeff3`）。冷暖錯配會讓切換主題時覺得像是兩個不同的網站。
- **細線透明度需微調**：暗底上人眼對極淡灰線的感知與淺底不同，通常維持在 `rgba(fg, 0.09 ~ 0.11)` 最為克制優雅，超過 `0.18` 就會變成刺眼的鐵絲網。

## 第 7 章｜中英混排與字體建築學（CJK × Latin Typography Craft）

當你捨棄花俏圖形、卡片陰影與漸層色塊後，**字體排版就是畫面上 80% 的視覺建築**。中英混排（CJK × Latin）更是區分業餘模板與頂級工藝的分水嶺。

### 7.1 絕對鐵律：永不對中文使用 `font-style: italic`

- 西文襯線字體（如 `Newsreader`、`Georgia`）有專門設計的真正斜體（True Italic）字形，具有優雅的手寫筆意；但中文宋體／黑體（`Noto Serif TC/SC`、`Noto Sans TC/SC`）在瀏覽器中**幾乎沒有真斜體字型檔**。
- 一旦對包含中文的段落套用 `font-style: italic`，瀏覽器會強制執行仿斜變形（Faux-Oblique Skew），將原本端莊平衡的漢字硬生生向右推倒 12–15 度，導致筆畫粗細失真、結構歪斜、極度廉價。
- **正確做法**：中文想表達詩意、強調或人文氣質時，應使用**正體宋體／明朝體**、適度放寬微字距（`letter-spacing: 0.02em ~ 0.04em`）、拉開行高（`line-height: 1.65 ~ 1.8`）並調低墨色對比（`--fg-2`），呈現從容安靜的印刷感。

### 7.2 字體三聲部編排原則（Three Typographic Voices）

高階介面通常不超過 **2–3 個清晰的字體聲部**，每個聲部職責嚴格分工：

1. **敘事／雕塑聲部（Display & Voice）**：承載主名號與核心一句話。可以是人文正體宋體（`Noto Serif TC/SC`）或極具現代張力的幾何無襯線。
2. **介面結構聲部（UI & Navigation）**：承載連結標題、說明與按鈕。選擇中性、字重均勻、能與中文無襯線平滑銜接的拉丁字體（如 `Geist`、`IBM Plex Sans`、`Inter` 啟用 stylistic sets）。
3. **技術座標聲部（Telemetry & Coordinates）**：承載網域、Handle、ASN、年份、時間、狀態碼與鍵盤指令。一律採用高品質等寬字體（`Geist Mono`、`IBM Plex Mono`、`JetBrains Mono`）並加上 **`font-variant-numeric: tabular-nums`**，確保數字寬度統一、切換或對齊時不左右跳動。

#### 推薦中英配對矩陣（依氣質選擇，不死背單一組）

| 氣質定位 | 中文主字體 | 拉丁搭配 | 等寬座標字體 | 視覺印象 |
| :--- | :--- | :--- | :--- | :--- |
| **人文詩意 × 現代克制** | `Noto Serif TC/SC`（400/600 正體）＋`Noto Sans TC/SC` | `Geist`（300/400/500） | `Geist Mono` | 溫暖、從容、展覽畫冊與工程品味的完美交會 |
| **瑞士精密 × 硬核工程** | `Noto Sans TC/SC`（400/500/600） | `Geist` 或 `IBM Plex Sans` | `IBM Plex Mono` | 冷靜、銳利、高度建築化、零懷舊感 |
| **溫潤出版 × 數位花園** | `Noto Serif TC/SC` / `LXGW WenKai` | `Newsreader`（僅限純英文正體／斜體）＋`IBM Plex Sans` | `IBM Plex Mono` | 書卷氣、長文極舒適、有手稿感 |
| **極速系統原生流** | 系統原生黑體（`PingFang TC/SC`, `Microsoft JhengHei`） | `-apple-system, BlinkMacSystemFont` | `ui-monospace, SFMono-Regular` | 零額外字體下載、零閃爍、瞬開質感 |

### 7.3 繁／簡／英三語切換的字體與長度紀律

- **精準語系字體切換**：使用 `:root:lang(zh-Hans)` 覆寫 `--font-serif` 與 `--font-sans`，讓繁體走 `Noto Serif/Sans TC`、簡體走 `Noto Serif/Sans SC`，避免字形骨幹混用（如「骨」、「直」、「畫」、「這」在繁簡字型標準不同）。
- **字重與載入減肥**：只引入真正用到的字重（例如 `400;500` 或 `400;600`），避免一次載入 `100..900` 全部字重與 7–8 個字族拖垮首屏。
- **跨語系長度膨脹防呆**：英文文案通常比中文長 **1.6× 到 2.4×**（例如「自治系統連通性」7 字 → `Autonomous system connectivity` 30 字元）。
  - 凡是包含多語文案的橫向彈性列，必須預留寬鬆間距或允許 `flex-wrap: wrap`，絕不假設所有語系都只有 6 個中文字寬。
  - 按鈕或低語讀數若在點擊後動態切換成「已複製 / Copied」，需設計為**不會推擠右側其他元素**的位置（例如置中對齊、靠左獨立成行、或設 `min-width` 穩定容器）。

### 7.4 流體尺度、字距與光學出血對齊

- **敢於拉開尺度差**：主標題使用 `clamp(3rem, 5.6vw, 4.85rem)` 甚至 `clamp(4rem, 9.5vw, 7.75rem)`，次要技術座標使用 `0.72rem ~ 0.78rem`（11.5px–12.5px），形成強烈的平面海報層級。
- **字距微分**：
  - 超大字標題：負字距 `letter-spacing: -0.02em ~ -0.045em`（中文收斂在 `-0.02em` 以內避免筆畫相撞；拉丁大字可收至 `-0.04em`）。
  - 詩意中文短句：微正字距 `letter-spacing: 0.02em ~ 0.04em` 增添呼吸感。
- **光學出血對齊（Optical Bleed Alignment）**：
  ```css
  /* 靜止時文字與整頁垂直軸線 0px 誤差對齊；懸停時底色向外柔和溢出 */
  .bleed-row {
    margin-inline: -0.75rem;
    padding: 0.75rem 0.75rem;
    border-radius: 8px;
    transition: background-color 150ms cubic-bezier(0.2, 0.8, 0.2, 1);
  }
  ```

## 第 8 章｜靜中有活：克制微互動與前端物理工程實作庫

### 8.1 動態設計五大憲法

1. **靜止即安靜**：沒人操作時，頁面上不該有任何循環閃爍、跳動或旋轉的干擾物。
2. **只為人的意圖而動**：每一次過渡與繪製都回應使用者的 hover、focus、click 或游標移動。
3. **快速、乾脆、帶自然減速**：偏好 `cubic-bezier(0.22, 1, 0.36, 1)` 或 `cubic-bezier(0.2, 0.8, 0.2, 1)`，時間控制在 `140ms ~ 340ms`，絕不做超過 `600ms` 的遲緩浮動。
4. **絕不觸發 Layout Shift（CLS = 0）**：互動只改動 `transform`、`opacity`、`color`、`background-color`、`border-color`、`stroke-dashoffset`，不改變字重粗細造成文字寬度跳動、不改變 `height`/`padding`。
5. **雙重硬體與無障礙保護**：
   - 懸停與鄰項降暗一律包在 `@media (hover: hover)` 裡。
   - 游標類 Canvas 特效必須同時檢查 `window.matchMedia('(pointer: fine)').matches` 與 `!prefers-reduced-motion`。
   - CSS 底部一律提供 `@media (prefers-reduced-motion: reduce)` 統一關閉所有過渡。

---

### 8.2 六大高階克制互動實戰模式

#### 模式 A｜純 CSS `:has()` 鄰項降暗（焦點聚光燈）
滑過群組中的任一項目時，不需要一行 JavaScript，其餘兄弟項目自動退暗至 `0.34 ~ 0.45`，瞬間創造美術館聚光燈般的聚焦感：

```css
@media (hover: hover) {
  .way-arc:has(.way-item:hover) .way-item:not(:hover) {
    opacity: 0.34;
  }
}
```
> **關鍵細節**：如果沒有包在 `@media (hover: hover)` 內，手機觸控點擊後返回頁面時，該項目會殘留 `:hover` 狀態導致其他所有連結看起來都灰暗半透明！

#### 模式 B｜GPU 加速細線掃描（Hairline Sweep）
比整塊按鈕變色高階得多的細節——在列表頂邊或左軸放置 `1px` 或 `2px` 偽元素，平時 `scaleX(0)` / `scaleY(0)` 隱藏，懸停時由原點絲滑展開：

```css
.row {
  position: relative;
}
.row::before {
  content: "";
  position: absolute;
  top: -1px;
  left: 0;
  right: 0;
  height: 1px;
  background: var(--accent);
  transform: scaleX(0);
  transform-origin: left;
  transition: transform 240ms cubic-bezier(0.22, 1, 0.36, 1);
}
@media (hover: hover) {
  .row:hover::before {
    transform: scaleX(1);
  }
}
```

#### 模式 C｜即時幾何 SVG 貝茲軌跡連線（Living Spatial Traces）
讓頁面上的焦點原點與遠處航點產生真實空間連結，且絕不因視窗縮放、字體載入或語系切換而對歪：

```js
const pathCache = new Map();

const buildCurve = (ox, oy, tx, ty, kind) => {
  const dx = tx - ox;
  const dy = ty - oy;
  if (kind === 'horizontal') {
    const c1x = ox + dx * 0.42;
    const c1y = oy + dy * 0.08;
    const c2x = ox + dx * 0.66;
    const c2y = ty;
    return `M ${ox.toFixed(1)} ${oy.toFixed(1)} C ${c1x.toFixed(1)} ${c1y.toFixed(1)}, ${c2x.toFixed(1)} ${c2y.toFixed(1)}, ${tx.toFixed(1)} ${ty.toFixed(1)}`;
  }
  const c1x = ox;
  const c1y = oy + dy * 0.58;
  const c2x = tx;
  const c2y = oy + dy * 0.55;
  return `M ${ox.toFixed(1)} ${oy.toFixed(1)} C ${c1x.toFixed(1)} ${c1y.toFixed(1)}, ${c2x.toFixed(1)} ${c2y.toFixed(1)}, ${tx.toFixed(1)} ${ty.toFixed(1)}`;
};

// 觸發描線繪製（從原點長向目標）
const activateTrace = (activePath, d) => {
```

1. 首次初始化 `updateTraces()`
2. `window.addEventListener('resize', updateTraces, { passive: true })`

4. `document.fonts.ready.then(updateTraces)` 與切換語言後的 `requestAnimationFrame(updateTraces)`

#### 模式 D｜上下文原點低語讀數（Contextual Whisper Readout）
將「說明文字／網域／複製回饋」統一收束到畫面核心原點旁的一塊極簡兩行讀數區（`aria-live="polite"`）：
- **靜止時**：顯示核心身分與狀態（如 `AS213876` / `開放對等 · 全球連通`）。
- **懸停／鍵盤聚焦任一航點時**：柔和切換為該航點的真實主機與簡短註解。
- **點擊任一複製按鈕時**：暫時鎖定顯示複製的值與「已複製」，1.5 秒後優雅歸位。
- **優點**：整張頁面因此不再需要在每個連結旁邊堆滿冗長的灰色說明文，空間瞬間開闊一倍，互動卻更豐富。

#### 模式 E｜零閒置耗能 Canvas 微痕系統（Idle-Sleeping Ink Filament）
若母題與「筆觸、軌跡、水面、光絲」有關，可實作超輕量按需 Canvas，嚴格守住四個上限：
- **線寬極細**：`0.6px ~ 1.35px`（隨時間衰減收細）。
- **透明度極低**：最大值 `0.15 ~ 0.20`，使用平方衰減 `fade * fade` 柔和蒸發。
- **零閒置耗能**：當 `points` 清空後將 `rafId = null` 停止 `requestAnimationFrame`，不動滑鼠時 CPU 與 GPU 佔用嚴格為 **0%**。
- **跨躍防直線**：相鄰採樣點距離 `> 110px` 時跳過連線（避免滑鼠切出視窗再切回時劃出一條難看的長直線）。
- **裝置過濾**：僅在 `pointer: fine` 且 `pointerType === 'mouse'` 且未啟用減少動態時啟動。

#### 模式 F｜通用無障礙一鍵複製系統
- 任何需要複製的按鈕都只需加上 `data-copy="目標字串"`。
- 優先使用 `navigator.clipboard.writeText()`，失敗時自動降級至離屏只讀 `<textarea>` + `document.execCommand('copy')`。
- 視覺反饋同時支援按鈕圖示切換（`copy` → `check`）、主讀數區提示、以及行動端獨立文字反饋，並搭配 `aria-live="polite"` 照顧螢幕閱讀器。

### 9.1 單色 Logo／Favicon 轉透明 Alpha CSS Mask 實戰

當專案只有一張深色剪影 `.ico` 或 `.png`（且可能暗藏白色圓角背景方塊），千萬別直接用 `<img>` 加 `filter: invert()`。應先提取純透明 Alpha 遮罩，再用 CSS `mask`＋`currentColor` 渲染：

```bash
# 1. 從 favicon.ico 最大幀抽出純淨灰階反相作為 Alpha 遮罩，並裁切留白、輸出 160x160 Retina 透明 PNG
magick "public/favicon.ico[8]" -background white -alpha remove -alpha off \
  -colorspace Gray -negate -level 10%,82% -trim +repage \
  -resize 144x144 -gravity center -background black -extent 160x160 /tmp/mask_a.png

magick -size 160x160 xc:black /tmp/mask_a.png -alpha off -compose CopyOpacity \
  -composite -strip -define png:compression-level=9 src/assets/mark.png

rm -f /tmp/mask_a.png
```

在 CSS 中使用**自訂屬性單次宣告 URL**，避免 Vite / LightningCSS 把小圖的 Base64 重複內嵌兩次：

```css
.brand-mark {
  --mark-mask: url("./assets/mark.png");
  display: inline-block;
  width: 34px;
  height: 34px;
  background-color: currentColor; /* 自動跟隨淺色、深色與懸停強調色 */
  -webkit-mask: var(--mark-mask) no-repeat center / contain;
  mask: var(--mark-mask) no-repeat center / contain;
}
```

### 9.2 Zero-FOUC 主題初始化與系統跟隨範本

在 `<head>` 中、任何渲染發生前，用一段極短同步內聯腳本鎖定 `data-theme` 與瀏覽器頂部狀態列 `theme-color`，徹底杜絕深色模式載入瞬間閃白：

```html
<meta id="theme-color-meta" name="theme-color" content="#f2efe9" />
<script is:inline>
  try {
    const saved = localStorage.getItem('theme');
    const prefersDark = window.matchMedia && window.matchMedia('(prefers-color-scheme: dark)').matches;
    const theme = saved === 'light' || saved === 'dark' ? saved : prefersDark ? 'dark' : 'light';
    document.documentElement.dataset.theme = theme;
    const meta = document.getElementById('theme-color-meta');
    if (meta) meta.setAttribute('content', theme === 'dark' ? '#10100e' : '#f2efe9');
  } catch {}
</script>
```

並在主腳本中監聽作業系統即時切換（僅當使用者尚未手動鎖定偏好時生效）：

```js
const media = window.matchMedia && window.matchMedia('(prefers-color-scheme: dark)');
if (media && typeof media.addEventListener === 'function') {
  media.addEventListener('change', (e) => {
    const saved = read('theme');
    if (saved !== 'light' && saved !== 'dark') {
      applyTheme(e.matches ? 'dark' : 'light');
    }
  });
}
```

### 9.3 連結安全、SEO 與乾淨輸出守則

- **外連參數守衛**：幫外部網址附加來源追蹤參數（如 `?ref=domain`）時，務必判斷協定僅處理 `http:`／`https:`，且避開 `mailto:`、`tel:` 以及依賴純淨路徑喚起原生 App 的連結（如 `t.me/`）。
- **結構化資料完整同步**：新增聯絡方式（Email、Telegram）或所屬組織時，同步更新 `<script type="application/ld+json">` 中的 `email`、`affiliation` 與 `sameAs`，同時顧好搜尋引擎與社群卡片預覽（Open Graph / Twitter Card）。
- **零註解輸出**：在 Astro 等模板中一律使用框架註解（`{/* ... */}`），避免開發註解殘留在最終線上 HTML 裡。

### 9.4 交付前十二道殘酷自審清單

在向使用者展示成果之前，必須逐一通過以下 12 道考驗（只要有一題心虛，就繼續改）：

1. **去字測試**：遮掉所有文字後，這是一套通用模板，還是只屬於這個主題的空間作品？
2. **破局測試**：我是否依然不自覺地畫了標準頂欄、卡片網格或居中豎管？
3. **溫度測試**：畫面摸起來有沒有材質與光感溫度，還是像冰冷的醫院表單？
4. **克制測試**：靜止盯著畫面 5 秒鐘，有沒有任何多餘的閃爍、浮動或花哨裝飾？
5. **母題測試**：頁面上最強的視覺或互動細節，是否直接呼應這個對象的核心靈魂？
6. **誠實測試**：有沒有擅自捏造假數據、假指標、或硬塞使用者沒要的內容來湊版面？
7. **CJK 測試**：中文字有沒有誤套 `italic`？繁簡切換字形是否正確？數字有沒有開 `tabular-nums`？
8. **素材測試**：Logo／圖示在淺色與深色模式下邊緣是否完全乾淨、無白框／黑框？
9. **四斷點測試**：`375px` 手機、`640px` 大手機、`1024×700` 小筆電、`1440×900`–`2560×1440` 大螢幕是否都無碰撞、無爆版？
10. **觸控與鍵盤測試**：手機點擊後會不會卡住 `:has()` 降暗？純鍵盤 `Tab` 瀏覽時焦點清晰且順序自然嗎？
11. **多語長度測試**：切到最長語系（例如英文）時，按鈕、標題與附註是否從容不擠壓？
12. **自動化建置測試**：正式建置是否 0 錯誤？內聯腳本語法、三語 i18n 鍵值完整性與外部連結是否全部通過腳本檢查？

### 9.5 自動化建置與品質驗收腳本範本

